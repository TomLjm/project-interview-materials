# 面试深挖 Q&A 编写规范

## 核心要求

- 对每个面试可能深挖的问题，**直接给出合理的分析作答**，不套用固定格式（如「意图/框架/追问」三段式）。
- 回答是「面试现场会怎么说」的分析版本：展示推理过程、取舍依据和数字锚点，而不是罗列背诵要点。

## 回答怎么写

- 先给结论、再给分析：为什么这样做、背后原理是什么、和替代方案如何取舍；
- 嵌入真实数字、公式与参数口径；第一人称、口语化；
- 对有争议或证据不足的点，主动交代边界与局限，体现判断力；
- 可以自然带出「如果面试官继续问 X，我会答 Y」，但不写成固定栏目。

## 问题分类（覆盖范围清单，不强制逐类）

1. **项目总览类**：一句话介绍、核心难点、最大贡献——回答给「定位 → 背景 → 分模块行动（各带数字）→ 收尾」的完整脉络。
2. **背景/动机类**：为什么做这个方案、不用现成方法——从数据/合规、适配深度、可控性、技术壁垒等角度展开。
3. **工作模块深挖类**：针对每个模块的做法、参数、阈值、流程、为什么这样设计；关键参数都要能回答「怎么定的、有什么局限」。
4. **原理类（深度核心）**：算法/模型原理推导、损失函数、为什么 A 而非 B/C——给公式、机制与替代方案对比。
5. **实验/指标类**：指标选型、提升归因、消融、对照——覆盖控制变量与数据口径。
6. **协作/分工类**：哪些独立完成、如何协作——主动区分团队与个人边界。
7. **挑战/复盘类**：踩坑、最大挑战、重做改进——按「问题→排查→解决→沉淀」讲真实案例。
8. **开放方向类**：下一步规划、对前沿的看法——展示技术视野。

## 数量与形式

- 建议 20–40 题，按项目复杂度调整；核心模块至少 2–3 题。
- 可在末尾附「高频补充题速答」：问题 + 一句话速答，适合碎片时间。
- 科研项目与实习项目通用；科研项目的「业务价值」替换为「学术价值/论文贡献」。

## 常见技术追问题库（按项目技术栈选用）

- 微调：LoRA 原理与推导、r/α 怎么定、与全参/Adapter/Prompt Tuning 对比、QLoRA。
- 分布式训练：DeepSpeed ZeRO 1/2/3 分别切分什么、为何不用张量并行、混合精度。
- 多模态：CLIP 与 DINOv2 特征差异、图文对齐机制、Cross-Attention 注入 vs 拼接、损失掩码。
- 生成模型：Diffusion 与 Flow Matching 的目标函数与区别、采样步数、VAE 的多解性与 KL。
- 检索：FAISS IVF/PQ/HNSW 原理、精确 vs 近似、重排与召回。
- 数据工程：清洗规则与阈值标定、自一致性过滤、难例挖掘/认知差距、抽检与统计口径。
- 3D/点云：Kabsch/SVD 求 SE(3)、canonical frame、形状补全、点云编码架构、距离矩阵。
