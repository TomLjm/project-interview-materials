# project-interview-materials

你在面试中是否讲不清自己的项目？明明项目做得很深，讲出来却像流水账？准备了一大堆问题，却总是答不到面试官想要的点上？

这个项目把「项目面试材料生成」沉淀成一套可复用的 Agent Skill：你可以选择提供岗位 JD、项目说明、源码仓库和简历，AI 就能结构化产出一份**用来背、用来复盘、用来被深挖**的中文面试材料。

## 这是什么

一个面向求职者（实习 / 校招 / 社招）的 AI Agent Skill。它不负责润色简历，而是解决面试里最容易被深挖、也最需要提前准备的部分 ——**项目**。

每份材料围绕三个核心：



1. **项目叙事**：面试时怎么讲。提供 30 秒一句话版本和 60–90 秒完整陈述，第一人称、口语化，可直接背诵；

2. **细节展开**：做法、原理、指标。团队整体工作与个人负责部分一眼可分，关键数字都能溯源到你的原始材料；

3. **面试深挖 Q\&A**：对每一个可能被追问的问题，直接给出「面试现场会怎么说」的分析作答，能顶住逐层往下挖。

## 核心特性



* **叙事优先**：产出的是「怎么讲」，不是要点列表；

* **事实忠实**：每个数字、指标、结论都来自你的材料，禁止编造，不确定的口径标注清楚；

* **边界清晰**：实习项目区分平台 / 团队成果与个人业绩，科研项目区分导师 / 团队工作与个人工作；

* **原理级深度**：损失函数 / 目标函数、超参选择依据、为什么用 A 方案而不用 B/C，都要求展开到原理层；

* **岗位对齐**：按目标岗位 JD 的关键词安排叙事顺序与详略，让面试官一眼看到匹配点；

* **直接分析式 Q\&A**：不套「意图 / 框架 / 追问」的固定模板，对每个问题给出合理的分析作答。

## 怎么用

这是一个依赖 AI 模型执行的 Skill（方法论 + 提示词规范，不是独立脚本），需要放到支持自定义 Skill 的 Agent 环境中：



1. 把本仓库目录（或其中的 `SKILL.md` 与 `references/`）放入你的自定义 Skill 目录，例如 `workspace/.user_skills/project-interview-materials/`；

2. 在对话中向 AI 提供以下材料（越多效果越好）：

* 目标岗位 JD（推荐）；

* 项目说明文档（docx /md/pdf）；

* 项目源码仓库（repo）；

* 简历中该项目的描述；

1. 提出「为 XX 项目生成面试材料」即可。

### 输入清单



| 材料                        | 必要性          |
| ------------------------- | ------------ |
| 项目说明文档，或 repo + 简历 bullet | 必须（能还原项目即可）  |
| 目标岗位 JD                   | 推荐（用于岗位对齐）   |
| 项目源码 repo                 | 推荐（用于确认技术细节） |

repo 探查要点：读 README、核心模块、关键配置 / 脚本、依赖清单，识别技术栈与数据流 —— 不要只看目录名。

### 输出结构（参考框架，非强制）



```
1. 项目叙事陈述（开头必备）
   30 秒一句话版本 + 60–90 秒完整陈述
2. 项目细节展开（按需增删）
   背景与动机 / 团队整体 vs 个人负责 / 工作模块 / 原理级细节 / 实验指标 / 成果价值 / 技术栈
3. 面试深挖 Q&A（必备）
   对每个可能深挖的问题直接给出分析作答
附：一页速记记忆卡（可选）
```

## 示例

> 以下为虚构示例，用于展示产出形态。

**30 秒版本**

> 我做的项目是面向电商客服的意图识别系统。核心是用意图树 + 槽位抽取替代传统意图分类：我在 500 万条真实对话上构建了 23 类意图的标注 pipeline，用两阶段模型把识别准确率从 86% 提升到 94%，推理延迟控制在 30ms 以内，上线后转人工率下降了 12%。

**Q\&A 片段**

> **Q: 为什么用意图树而不是直接多分类？**
> 直接多分类在 23 类上会频繁出现相近意图混淆，而且无法表达「下单 → 改地址 → 催发货」这种对话级意图流转。我改用意图树后，上层粗分类 + 下层细分类，混淆误差下降了约一半；代价是多了一层决策，我用蒸馏把推理延迟控制回 30ms 以内。
